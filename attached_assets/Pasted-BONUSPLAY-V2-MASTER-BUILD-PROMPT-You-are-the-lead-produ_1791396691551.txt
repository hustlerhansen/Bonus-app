THIS IS A CRITICAL SYSTEM.

Do NOT implement points as a simple editable number on the user record.

Build a proper immutable points ledger.

Create a transaction model.

Balance must be calculated reliably from valid ledger transactions or maintained through an atomic balance system backed by the ledger.

Never trust point values coming from the browser.

All points calculations must happen server-side.

Prevent:

Duplicate rewards
Replay attacks
Double redemptions
Negative balances
Race conditions

Use database transactions where appropriate.

Implement idempotency.

Example:

A conversion ID can only reward a user once.

48. CRITICAL FINANCIAL RULE

BonusPoints represent a financial liability for BonusPlay.

Therefore:

Points must never be created, duplicated, redeemed or reversed without a traceable ledger event.

Every point must be explainable.

We must always be able to answer:

Where did these points come from?

Why were they awarded?

Were they verified?

Were they redeemed?

Were they reversed?

Who changed them?
